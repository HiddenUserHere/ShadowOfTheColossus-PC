# L1: honest labels by deferral (SOTC_LABELS_HONEST)

Component L1 of DRAW-THREAD-DESIGN.md (sections 4.2 row L1 and 4.3). Wave 1, agent l1.

## What changed

### gpu/sotc/label_honest.h, gpu/sotc/label_honest.cpp (new, owned)

- `SotcLabels::On()`: `SOTC_LABELS_HONEST=1`, read once. Default off.
- `SotcLabels::Honest()`: `On()` and the machinery is live (set by the Liverpool constructor when the
  draw thread runs and the switch is on). For the F2 agent (gnmdriver.cpp frame pipelining) to gate on.
- `SotcLabels::MarkLive()`: called by the Liverpool constructor.
- `SotcLabels::NoteSharedTouch()` and `SotcLabels::SharedSeq()`: a lock-free counter. Other agents call
  NoteSharedTouch when recorded GPU work reads or writes HOST_SHARED or GPU_TO_CPU memory.
- `SotcLabels::Kind` (Eop, ReleaseMem, Eos), `NoteLabel`, `NoteExcluded`, `NoteForced`,
  `ReportLabels(std::string&, double)`: counters, reset on each report like ReportCpLabelSkip.

### gpu/shadps4/video_core/amdgpu/liverpool.h (owned)

- `RbxJob::label_kind` (SotcLabels::Kind), set where a deferred label is tracked (Ring8Track).
- Members `labels_honest`, `label_machinery`, `label_ring_seq[2]`, `label_shared_seq[2]` (per queue:
  0 graphics, 1 compute), `struct LabelDecision`, and `LabelDecide(kind, q, label, waited)`.
- `#include "../../../sotc/label_honest.h"`.

### gpu/shadps4/video_core/amdgpu/liverpool.cpp (owned)

- `Liverpool::Liverpool`: `labels_honest = back_threaded && !rbx && SotcLabels::On()`. When it is on,
  `ring8_labels` is forced on (the deferred-label machinery: Ring8Track, watchdog, BackLoop poll, CP wait
  step). `label_machinery = ring8_labels && (Mode() == 8 || labels_honest)`. The switch is refused, with a
  warning, when there is no draw thread or when SOTC_RB_EXACT is on (see Risks).
- `Liverpool::LabelDecide` (new, next to Ring8Track): the one deferral rule for all three label kinds.
  - ring8 rule (mode 8): HostWriteSeq changed since the queue's previous label;
  - honest rule (switch on): SharedSeq changed since the queue's previous label;
  - outstanding: a deferred label is still outstanding (labels land in order, as before).
  - `waited` (lookahead) or a learned CP wait on the label excludes it.
  - Counts into SotcLabels (seen, deferred, honest-only, excluded).
- EOP (`EventWriteEop`): the decision is `LabelDecide` (queue 0). With the switch off it gives exactly the
  old result (same pending test, same learned-wait test, same counters).
- EOS (`EventWriteEos`, SIGNAL_FENCE only, not GDS store): new lookahead `eos_waited`; a deferred branch
  before the existing rbx path (queue 0). It invalidates the page's GPU copy as EOP does, and uses
  QueueDeferredLabel with shadow32, Ring8Track and Flush. The `label_kind` is Eos.
- ReleaseMem (`ProcessCompute`): new lookahead `rm_waited` (see Risks, stale graphics set); a deferred
  branch (queue 1) next to the existing rbx branch. The `label_kind` is ReleaseMem.
- `ProcessCompute` WAIT_REG_MEM spin: calls `Ring8CpWaitStep` while a deferred label is outstanding, with
  `labels_honest` only. Without it a compute wait on a deferred label waits for the 500 ms watchdog.
- `Ring8ScanSubmit`, `Ring8NoteCpWait` (both queues), the EOP lookahead: gated on `label_machinery`
  instead of `ring8_labels && Mode() == 8`. Same result with the switch off (only the learned-key
  bookkeeping now also runs in mode 8 with SOTC_PC_RING8_LABELS=0, where the keys were unused).
- `Ring8Watchdog`: `SotcLabels::NoteForced(job->label_kind)` next to the existing forced counter.

Default behaviour (switch off): the EOP, watchdog and CP spin code paths are unchanged. The compute spin
gets no new call. EOS and ReleaseMem take no new branch (`labels_honest` false). Verified by reading the
diff; not run in game.

## Counters

Report line from `SotcLabels::ReportLabels` (the line is not printed while the switch is off):

`SOTC labels honest: seen N, deferred D (x%), honest-only H (y%, gate <2%, z/s); EOP s/d/h/x/f, RM s/d/h/x/f, EOS s/d/h/x/f (seen/deferred/honest-only/excluded/forced)`

- seen: labels that went through the rule (per kind).
- deferred: labels the rule deferred (ring8 rule, shared-touch rule or outstanding).
- honest-only: deferred only because of the shared-touch rule (no ring8 hit, no outstanding label). This
  is the cost count. The gate is honest-only / seen < 2%. The percentage in the line is over all kinds.
- excluded: a rule applied but the label is waited on (submit lookahead) or was learned as a CP wait.
- forced: deferred labels written by the 500 ms watchdog (per kind).
- The existing pc_ring counters (`SotcPcRing::NoteHostLabel*`, `NoteHostLabelForced`) are unchanged and
  still count EOP only; the forced one now also covers RM and EOS jobs (ring8_jobs holds all kinds).

## Deadlock argument (also in liverpool.cpp above LabelDecide)

A deferred label is in ring8_jobs and has three ways out:
1. The GPU finishes its tick. BackLoop polls Ring8Service and EopService while eop_outstanding is non zero,
   so PopPendingOperations and LandOnce run on the draw thread without any CP action.
2. A CP WAIT_REG_MEM on the label (graphics spin: existing; compute spin: new, gated on labels_honest)
   calls Ring8CpWaitStep. It flushes the open buffer once per wait, and queues Ring8Service, so the GPU
   runs the work before the label.
3. The 500 ms watchdog (Ring8Watchdog, run from Ring8Service, so from BackLoop) lands it.

The lookahead keeps the common case out of (2): a label that the same gfx submit waits on (ProcessGraphics
scan, Ring8ScanSubmit, which walks DCB, CCB and called IBs) is never deferred, and a label already seen as
a CP wait (learned set, Ring8NoteCpWait) is not deferred either. A wait that is learned later is covered
by (2) and (3). No CP wait can wait forever: (3) bounds every deferred label by 500 ms even if the GPU
never ran it.

## Risks

- Compute lookahead is partial. Ring8ScanSubmit scans graphics submits only, so the ReleaseMem lookahead
  uses the last scanned graphics submit's waits plus the learned set. A compute wait that is not yet
  learned can see a deferred fence. It then costs a flush (2) or, at worst, 500 ms (3), not a hang.
- SOTC_RB_EXACT: the switch is refused when rbx is on. The new deferrals skip rbx's owed-download and
  rule-7 bookkeeping (no RecordLabelDownloads, EOS snapshot only); enabling it with rbx would be untested.
- Cost: with the switch on, ScanSubmit and the CP wait keys run in every mode (IB walk per gfx submit,
  mutex per wait). Mode 8 already pays this; other modes pay it only with the switch on.
- Outstanding chain: once a label is deferred, all later labels of any queue are deferred until the
  outstanding count reaches 0 (existing rule). The shared-touch rule can start that chain more often.
  The honest-only count is the measure of that cost.
- Forced labels can publish a value early (the existing caveat of Ring8Watchdog).
