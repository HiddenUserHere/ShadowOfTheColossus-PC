# D1: descriptor strategy, buffer device addresses behind SOTC_BDA (wave 1)

Scope: groundwork only, behind `SOTC_BDA` (off by default). Guest buffers that are neither texel nor
coherent are read and written through physical addresses taken from a GPU-side block table, instead of
through their descriptors. Descriptors are still declared and still bound by the host, so nothing is
removed yet. Nothing was built or run: syntax-only checks, see "Verified".

## What changed (file:function)

Recompiler, owned (`shader_recompiler/**`), every edit marked `sotc:`:

- `shader_recompiler/profile.h`: `Profile::bda_buffers` (new last member). The struct grows from 64 to 68
  bytes, because `stage_bindings` ends exactly at byte 63 (no padding left). See the cache note below.
- `shader_recompiler/resource.h`: `BufferType::BdaBlockTable`, appended at the end of the enum.
- `shader_recompiler/info.h`: `Info::HasBdaBlockTable()`.
- `shader_recompiler/ir/passes/shader_info_collection_pass.cpp`: `CollectShaderInfoPass`. When
  `profile.bda_buffers && profile.support_int64`, a shader with at least one non-texel Guest buffer and
  a free slot in `info.buffers` (`< NUM_BUFFERS`, the list is a static_vector of 40) gets one extra
  `BdaBlockTable` entry, pushed last. `info.uses_int64` is also set when the table exists.
- `backend/spirv/spirv_emit_context.h/.cpp`:
  - `EmitContext` ctor: `PhysicalStorageBuffer64` addressing when the table exists.
  - `DefineBuffers`: a Guest buffer that is not texel and not coherent (mtype 3) gets `spv_buffer.bda = true`
    and no OpVariable. Binding numbering is unchanged (`binding.buffer++`, `++binding.unified`).
  - New helpers: `LoadBdaBlock(handle)` (reads lo, hi, size from table slot `handle*4`),
    `BdaAddress(handle, index, elem_size, count)` (returns U64 address and a valid bool; invalid accesses use
    the block start as address), `BdaLoad` (loads, selects zero when invalid), `BdaStore` (guarded by a
    branch), `BdaPointer` (OpConvertUToPtr to PhysicalStorageBuffer), `BdaBeginIf` / `BdaEndIf`.
- `backend/spirv/emit_spirv_context_get_set.cpp`: B32xN, U8, U16, U64 loads and stores take the BDA path
  when `spv_buffer.bda`. Formatted and float/other types are unchanged.
- `backend/spirv/emit_spirv_atomic.cpp`: `BufferAtomicU32` (int and float), `IncDec`, `CmpSwap`,
  `BufferAtomicU64` take a guarded path: the atomic runs only when in range, and the result is a phi with zero.
- `backend/spirv/emit_spirv.cpp`: `PhysicalStorageBufferAddresses` capability and the extension, also when
  the table exists.

Host, owned new files:

- `video_core/renderer_vulkan/vk_bda_table.h/.cpp`: `BdaTableMode(instance)` (SOTC_BDA env, 0 without int64),
  `class BdaTable` (`Begin(num_slots, null_address)`, `SetBlock(slot, device_address, buffer_bytes, offset,
  size)`, `SetNull(slot)`, `Words()`, `Bytes()`), and `BdaTableReport(out, size)` (counters, reset on read).
  The class takes device addresses from the caller, so it does not depend on `buffer.h`.

## Switches and values

- `SOTC_BDA=1`: on. `SOTC_BDA=2`: on plus verify (a slot whose block lies outside its buffer is made null and
  counted in `verify_fail`). Unset or 0: off, identical SPIR-V to before (apart from the profile field).
- The gate is `Profile::bda_buffers`, set once per process from `BdaTableMode(instance) != 0` (snippet P1). It is
  part of the profile, so the shader cache is keyed by it.
- Per shader, the emission is decided by `info.buffers` (a table entry exists only when the profile flag is on
  and the shader has a non-texel guest buffer). The brief asked for a per-shader key; the profile-level flag
  achieves that, because every pipeline and module is compiled under the same profile and the cache check
  resets the whole cache when the flag changes.

## Shader cache (important)

- Toggling `SOTC_BDA` changes the profile, so the existing cache check (`vk_pipeline_serialization.cpp`,
  WarmUp) resets it: the shader cache is rebuilt the first time the switch is on, and again when it goes off.
  This is expected.
- Without snippet S1 below, the profile size changes from 64 to 68 bytes for everyone, so every user's
  cache is reset once, switch off included. S1 keeps 64-byte caches compatible with the flag off. Apply it
  with the change, or the switch-off path is not "no change".

## Counters (BdaTableReport, one line per 5 s when D1 is applied)

`SOTC BDA draws N slots N nulls N no_bda N misaligned N verify_fail N table N B`

- `draws`: stages bound with a table (Begin calls).
- `slots`: guest slots set (SetBlock calls).
- `nulls`: slots with size 0 (reads zero, writes dropped). Expected for unused bindings.
- `no_bda`: non-null slots whose buffer had no device address. **Must be 0**: such a slot reads zero where the
  descriptor path would read real data. Expect this with `SOTC_PC_RING=8` (borrowed imports, see risks).
- `misaligned`: blocks whose base is not 4-byte aligned (dword loads are declared Aligned).
- `verify_fail` (SOTC_BDA=2 only): block not inside its buffer.
- `table`: total bytes of table words written (16 B per slot).

## Risks

1. **Borrowed imports (SOTC_PC_RING=8, the default in sotc.py since f85137d)**: borrowed buffers have no
   device address, so their slots are null and reads return zero. Do not enable `SOTC_BDA` with ring8 until
   the imports get `eShaderDeviceAddress` and a queried address (buffer.cpp borrowed ctor, pc_ring import
   creation) and the table takes it. Until then `no_bda` shows the damage.
2. **No robustness on physical pointers**: `robustBufferAccess` does not cover them. Loads are clamped by
   the table size (out of range reads zero) and stores are guarded. The clamp trusts the host size. A block
   smaller than one element is read at its start (up to 3 bytes past its size, inside the buffer in practice).
   This is a deliberate difference, not a bounds guarantee.
3. **Coherence**: mtype 3 (shared, `Coherent`) buffers keep descriptors. Physical-pointer accesses have no
   `Coherent` decoration, so any Coherent buffer that moved to the table would need memory-model review.
4. **Alignment**: loads and stores are `Aligned` to the element size, which PhysicalStorageBuffer requires. A
   misaligned guest base is undefined behaviour in principle (counted in `misaligned`, not fixed).
5. **Barriers and sync bookkeeping**: the descriptors are still bound, so `bound_buffers`, `needs_barrier`
   and write marks still run for these buffers. Before the descriptors go, the barrier and write tracking
   must cover BDA access to the same ranges (not done).
6. **Int64**: needed for the addresses. Intel Iris Xe (no shaderInt64) gets the flag off. Arc has int64.
7. **Vendors (not tested)**: NVIDIA: PhysicalStorageBuffer is supported on all Vulkan 1.2 drivers, and the
   8/16-bit capabilities are already added. AMD: same. Intel: no int64 on older parts (flag off). The
   `Aligned`-access rule and clamped reads are portable; the performance of three table loads per access
   is not known.
8. **Performance**: each access reloads its block from the table (3 loads, a compare and a select). A
   per-shader hoist of the block loads to the function start would cut this; not done.
9. **Cache reset**: toggling the flag resets the shader cache (see above). S1 avoids the reset for the flag off.

## Images (bindless heap): what remains

- Samplers already have a heap path (`SOTC_BINDLESS_SAMP`, set 1, indices in push constants). Images
  (sampled and storage) do not. The recompiler still defines one descriptor per image resource
  (`DefineImagesAndSamplers`), and the host resolves the T# to a view per draw.
- Needed: a runtime array of sampled images and of storage images, indexed by a slot from push constants;
  a persistent slot per (image view, T# variant). The view is not just the image: depth/stencil,
  cube-to-2D-array, format-substituted and metadata-fallback views change the descriptor, so the slot key
  must include them. The host writes a slot once per view creation and again on invalidation (no per-draw
  writes).
- Storage images in an array need `shaderStorageImageArrayDynamicIndexing` and, for R32 formats without
  a format qualifier, `shaderStorageImageReadWithoutFormat`. LOD feedback and the mip-storage fallback
  (`MipStorageFallbackMode`) use descriptors and need their own slots.
- Risks: descriptor indexing limits (`maxDescriptorSetUpdateAfterBindSampledImages` and per-stage limits on
  NVIDIA, AMD and Intel differ), non-uniform indexing (`shaderSampledImageArrayNonUniformIndexing`), and the
  heap's update-after-bind rules during command recording. Only the sampler half (`SOTC_BINDLESS_SAMP`) is
  measured.

## Full migration: what remains

1. Buffers: remove the Guest descriptor writes and the Guest entries from `info.buffers` (the layout shrinks).
   Requires the barrier and write-tracking change (risk 5) and a decision for texel buffers (formatted: keep
   descriptors, or decode the format in the shader).
2. Coherent buffers: a Coherent-equivalent for physical pointers, or keep their descriptors (current choice).
3. The table: one per draw for all stages (not per stage), with stable slots; a per-draw dirty check to
   skip the upload when nothing changed (the table is 16 B per slot).
4. Images: the bindless heap above.
5. Measurement: the `SOTC_BDA` counters, FPS on the attract benchmark, and the `BindBuffers` time (the
   BDA path should remove most of its guest work).
