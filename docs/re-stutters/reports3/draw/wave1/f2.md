# F2: frame pipelining (one frame of command-processor lead), wave 1

Component F2 of DRAW-THREAD-DESIGN.md §4.2. Built and syntax-checked only (no ninja, no game run,
per the wave brief). Status: implemented behind `SOTC_FRAME_AHEAD=1` (default off), not measured.

## What already existed (verified in code)

`SOTC_CP_AHEAD=2` already is a one-frame-lead gate: `gnmdriver.cpp` `GateWait` waits for
`recorded >= marked - SOTC_CP_AHEAD_FRAMES`, and that variable defaults to **1**. So
`SOTC_CP_AHEAD=2` alone already runs one closed frame ahead; F2 mostly adds the honesty gate, the
fixed lag, the counters and the dt clamp. Consequence: the reuse-distance exposure described below
already exists for anyone who runs `SOTC_CP_AHEAD=2` today.

## What changed

Owned file `gpu/shadps4/core/libraries/gnmdriver/gnmdriver.cpp` (and its `.h`):

- `FrameAheadRequested()`: reads `SOTC_FRAME_AHEAD` once (`=1` on, everything else off).
- `FrameAheadActive()`: latched at the first submit. On only when requested **and**
  `SotcLabels::Honest()` (gpu/sotc/label_honest.h, agent l1). If not honest it logs one warning
  and stays off, and the gate is exactly what `SOTC_CP_AHEAD` selects.
- `GateMode()`: `2` (frame tickets) when `FrameAheadActive()`, else `Liverpool::CpAheadMode()`.
  `GateWait` and `sceGnmSubmitDone` use it instead of `CpAheadMode()` directly; with the switch off
  the result is identical to before.
- Lag: `1` while active (`SOTC_CP_AHEAD_FRAMES` is ignored then), so at the first submit of frame K
  the draw thread has recorded K-2 and may still run K-1.
- `GateWait`: in the ticket branch, when active, it samples the lead (closed, not yet recorded
  frames) once per frame before waiting, and times the calls that actually block.
- `ReportFrameAhead(std::string& out)` (declared in gnmdriver.h): one line per window, resets the
  counters, prints nothing when off or when no frame started.

Counters (all reset by `ReportFrameAhead`):
- `frames`: frame starts sampled (first submit or doorbell after a `sceGnmSubmitDone`).
- `run ahead`: frame starts whose lead was 1 or more, i.e. the draw thread still had a closed frame in
  flight when the guest started the next one. Shown as a count and a percentage of `frames`.
- `lead 0/1/2/3+`: histogram of that lead. With the lag fixed at 1, the lead after the gate is never
  above 1, so only the sample before the wait is meaningful, and that is what is counted.
- `gate waits`, `ms`, `max ms`: gate calls that had to block on `WaitFramesRecorded`, total time and
  the longest one.

Line format: `SOTC FRAME AHEAD: frames N, run ahead N (P%), lead 0/1/2/3+ a/b/c/d, gate waits N (T ms, max M ms)`.
No sample output exists yet (nothing was run).

`liverpool.{h,cpp}` is agent l1's; the change needed there is snippet 1 below, and it is required.
Without it `frame_tickets` stays false, `SubmitDone` never pushes a frame mark, `FramesMarked()`
stays 0, and the ticket gate passes at once: the guest would run unbounded ahead of the draw thread
with no lag limit at all. It would not deadlock, but it is the opposite of the intended bound.
Do not turn the switch on before snippet 1 is in.

## Guest-visible ordering assumptions (and how each holds)

Listed in the code comment too (gnmdriver.cpp, the `SOTC_FRAME_AHEAD` block).

1. **GPU progress the guest can see is produced by the draw thread in stream order** (labels, EOP/EOS/
   RELEASE_MEM interrupts, WRITE_DATA, flip). A one-frame lead only delays them. Holds (verified in
   the existing comment and `liverpool.cpp` label paths; unchanged by F2).
2. **Guest memory read by an op is read at record time** (staging, host import at record). A frame
   recorded before the guest reuses its memory is safe. Exception: HOST_SHARED memory that the host
   GPU reads in place after the label. That needs honest labels, which is why the gate requires
   `SotcLabels::Honest()` (`label_honest.h`: a label waits for the GPU when shared memory was touched).
   **Holds only if l1's deferral rule covers every op that reads HOST_SHARED; not checked here.**
3. **Command buffers and constants are parsed before reuse.** The frame ticket requires the command
   processor to parse all submits of a frame (`ServiceFrameMarks`) and the draw thread to record it.
   Holds for buffers reused after their frame is recorded.
4. **The game's own fences stay valid**: a label it waits on is seen only after the op that writes it
   was recorded (item 1). Holds.
5. **CPU writes are not ordered by the gate.** The game writes frame K+2's command buffers and
   constants before its first submit of K+2, while the draw thread may still run K. The gate at
   K+2's first submit waits for K-1 only (lag 1), so the guest's K+2 writes can start while K is still
   unrecorded. **Consequence: a buffer reused two frames later (double buffering) can be rewritten
   while frame K still reads it. Reuse distance of three frames or more is safe.** With the existing
   lag-0 gate, distance two was safe; lag 1 raises the requirement to three. This is the core risk:
   SotC's own reuse distance for command buffers, constants and the per-frame allocators is **not
   measured** (no reverse engineering was done for this). It is the first thing to check before
   enabling the switch in the game.
6. **`submission_lock` / GpuIdle IRQ are not used in this mode** (as in `SOTC_CP_AHEAD=2`): the
   tickets replace them; `ResetSubmissionLock` still runs and is harmless.

## Counters and what they mean for the gate

- `run ahead` > 0 means the lead happens (the CP really was one frame ahead).
- `lead 3+` should stay 0; it would mean the ticket accounting is off.
- `gate waits` count the times the guest actually blocked. Many waits at high `ms` would mean the
  lead does not hide the burst (the draw thread is behind by more than one frame).

- Pass criteria (from DRAW-THREAD-DESIGN §5 phase 3): frames > 50 ms halved against phase 2, no

  geometry), `lead 3+` = 0.
- Use one switch per comparison, alternate off/on in at least three one-round runs (`--repeat 1`).

## Risks

- **Double-buffer corruption** if the game's reuse distance is 2 (item 5). Could look like flicker or
  wrong geometry for one frame, mostly on the streaming and burst routes. This is the switch's main
  reason to stay off by default.
- **Honest() decided once.** The decision is latched at the first submit. If `Honest()` is false
  then and becomes true later, the run stays off. Acceptable for a boot-time property; say so if
  l1 makes it dynamic.
- **Lag and `SOTC_CP_AHEAD_FRAMES`.** While active, `SOTC_CP_AHEAD_FRAMES` is ignored. A user who
  set it to 0 with `SOTC_FRAME_AHEAD=1` gets lag 1 anyway. Documented in the code comment.
- **Cvar dt clamp is not verified** (see snippet 3).
