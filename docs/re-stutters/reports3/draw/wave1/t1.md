# t1: image churn and first use (image.cpp, image_prefetch.cpp)

Written by the coordinator from the agent's hand-back (the agent did not write the file). Nothing was run in game.

## What changed
- `image.cpp`: `SOTC_IMG_POOLED=1` (off): the image pool is on at 256 MiB (as with SOTC_VK_POOL=1;
  SOTC_IMAGE_POOL_MB still sets the size). New `CreateInImagePool()` used by UniqueImage::Create and
  TryCreateWithinBudget: existing pool blocks first (NEVER_ALLOCATE, as before); with the switch and a full pool,
  a new block of the pool's own. Switch off = the same calls as before. VMA never makes a dedicated allocation
  from a pool with an explicit block size (checked in vk_mem_alloc.h).
- `image_prefetch.cpp`: `SOTC_IMG_CREATE_AHEAD=1` also turns on the existing ImagePrefetcher (same as
  SOTC_ASYNC_IMAGE_CREATE=1): images created on 2 workers ahead of the draw thread (128 outstanding by default,
  SOTC_IMAGE_PREFETCH_MAX up to 4096).
- `ImageChurnReport()`: "SOTC IMG CREATE 5s: images created N (pool P, dedicated D), freed F, live L | ahead:
  queued Q (refused R), made M, used ready U, waited W, draw made X (taken back T), wasted E" (self-throttled,
  printed only with a switch on). Called from driver.cpp (applied).

## Not done
Pre-staging decoded textures at loader completion: the hook is game code (eboot ~0x148d14) and image creation
needs the T#-derived ImageInfo, which only the command processor has; SOTC_AREA_PREWARM=3 is the existing route.

## Tests (one round each)
default vs SOTC_IMG_POOLED=1 ("N dedicated" in SOTCSTALL ~0); default vs SOTC_IMG_CREATE_AHEAD=1
(+ SOTC_IMAGE_PREFETCH_MAX=512 for the ~710-image area-load burst).

## Risks
256 MiB VRAM preallocated at the first image; a full pool adds a 64 MiB block on the draw thread; the pool's
memory type is fixed by the first image; 2 s expiry can waste prefetched images.
