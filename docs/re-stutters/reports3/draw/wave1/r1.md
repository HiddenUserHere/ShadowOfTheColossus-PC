## 2. Switch

`SOTC_RB_HOST` (off by default; read once):

- `1`: mode 1. GPU writes the result ranges into imported host memory. Needs `SOTC_LABELS_HONEST=1` (else refused, counted).
- `2`: mode 2 (verify). Normal path stays (GPU buffer, tracking, readback). Mirror copy plus byte compare at readback apply. Needs the call-site snippets C and E below to produce anything.

Needed with it (for the stats and mask paths): `SOTC_PC_RING=8` (ring8 is the host-serving path, default in sotc.py), `SOTC_RB_CLASS=1`, `SOTC_RB_OWNER=1`, `SOTC_RB_MATERIALIZE=1`, `SOTC_HOOK_ALLOC_PROBE=1`, `SOTC_PARTICLE_PREV=1`, `SOTC_HOOK_XPRMEM_PROBE=1` (for `NoteMaskPointer`), `SOTC_HOOK_XPR_PROBE=1`.

## 3. Counters

Line `SOTC RB HOST mode N: ...` (per 5 s window, `SotcRbHost::Report`, printed by the FPS report):

- `stats runs noted /s`: `NoteStatsRange` calls accepted.
- `new granules /s`, `evicted /s`, `live N = X KiB`: the granule set. Evictions and new granules mean re-publish and re-import (cost).
- `refused`: calls refused in mode 1 without honest labels.
- `mask pointers /s, host-served %`: how many mask pointers BuildSetDraws writes already lie in a host-served run. This answers whether ring8 already covers the XPR masks (assumed yes, not measured).
- `served writes covered /s`, `label touches /s`: served writes into result ranges, and the subset reported to the label deferral (mode 1).

Line `SOTC RB HOST verify: ...`: ranges, bytes, **mismatched bytes (must be 0)**, no snapshot, mirror copies, unimported. Mismatches are logged to stderr (first 16 with address and first differing byte).

2. Mode 2 first: `SOTC_RB_HOST=2` plus the switches in section 2, and check the verify line: mismatched bytes must be 0 and mirror copies > 0. Only then:

4. Watch `new granules /s` and `evicted /s`: high churn means the publish/re-import cost dominates.

## 6. Risks

- **Ordering (mode 1), the main risk.** The game reads a stats array two calls after the count pass with no CPU-side wait in the port. Mode 1 is only safe if the game waits on a label that follows the dispatch (the L1 deferral is meant to make that so). Unverified. This is the same failure class as `SOTC_RB_CLASS=2` (vertex explosions). Do not trust mode 1 until mode 2 with a mirror is clean and an in-game artefact check passes.
- **Mode 2 proves the mirror, not the timing.** The compare happens at readback apply, after the GPU finished. It shows the mirror content is right, not that the game's read was not stale.
- **Publish cost.** `SetHostExtras` bumps a version on every change and the ring re-applies all runs (HANDOFF: heap serving cost 3-6 FPS for the same reason). The stats set changes most frames; this may cost FPS even if the readbacks drop.
- **Import cost.** Each new run is one import (`vkAllocateMemory`). 512 granules is a first guess; lower it after the churn counters are known.
- **GPU-modified granules.** Snippet A filters them; without it the ring serves a granule whose newest bytes are in the device copy.
- **`NoteMaskPointer`** looks at the pointers at entry (the previous build's masks, as in probe_xprmem's existing notes). It is a presence count, not an exact claim about the next build.
- **Header weight.** `rb_host.h` pulls `vk_common.h`, so `driver.cpp` (snippet D) now sees the Vulkan headers. Build time only.
- Thread-local caches in `Covers` (`t_cache`) are per thread, so the guest threads that reach `FinishAsyncReadback` get their own copy. Fine, but it means the first call per thread takes the mutex.
