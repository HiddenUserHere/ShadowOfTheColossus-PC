## 2. Counters (SOTC_PIPE_DIRTY=1 or 2)

Line in the 5 s report (call-site in section 4):

`SOTC pipe dirty: mode 1, graphics key register part rebuilt R, skipped S (x%), mismatches M; flat buf refreshed F, unchanged U (y%), W words each, Hz refreshes/s`

| Field | Meaning |
|---|---|
| rebuilt R | register parts built: snapshot differed, or first draw. Counted once per `RefreshGraphicsKey` call that reaches the key |
| skipped S (x%) | register parts taken from the cached copy; x = S / (R + S) |
| mismatches M | `=2` only: the cached register part differed from a rebuild. Must be 0 |
| flat buf refreshed F | `RefreshFlatBuf` calls on existing programs (graphics and compute stage path) |
| unchanged U (y%) | of those, refreshes whose words were identical to the previous ones. High y means a memory-generation skip (V1) would remove most refresh work |
| W words each | flat buffer words per refresh |

Note: the snapshot compare runs on every draw, in every mode 1/2 draw. Mode 2 also rebuilds on every hit,
so its timing is not representative.

## 3. Part 2: RefreshFlatBuf (why no skip)

`shader_recompiler/info.h` `RefreshFlatBuf()` copies the user data, then runs `walker_func`, which
calls `SrtCopyWindow` (`ir/passes/flatten_extended_userdata_pass.cpp:83`,
`Core::Memory::Instance()->CopySparseMemory(src, ...)`), and then `RefreshSharpTables()`
(`info.cpp:17`, copies sharp tables from guest memory). Verified in code. The words therefore depend on
guest memory that the game can rewrite without any register write, so a skip keyed on registers would
be stale. The safe skip needs a per-granule memory generation (DRAW-THREAD-DESIGN V1). The counters tell
whether that pays: if `unchanged` is high, most refreshes are wasted work.

## 5. How to test in game

Use the standing Lab rules: `user/routes/tests.json` for the route, `tools/pcmem_matrix.py --repeat 1`
for a round (both from the project memory).

1. `SOTC_PIPE_DIRTY=2`, one run: every 5 s line must show `mismatches 0`. Any nonzero value is a stale key
   bug; stop and report the window.
2. `SOTC_PIPE_DIRTY=1` against the base, at least three alternating runs: read `skipped %` and the
   draw/CP timers from the profile (CP thread, `GpuCommandProcessor` samples under `RefreshGraphicsKey`).
   The gate for keeping it is a measurable drop in `RefreshGraphicsKey` samples; the snapshot compare
   costs something on every draw, so a low skip rate is a loss.
3. `SOTC_PIPE_DIRTY=1` alone also gives the flat-buffer `unchanged %`. Use it to decide on V1.

## 6. Risks

- The register part must keep reading only registers. The header comment says to extend
  `PipeKeyRegs` for any new register read; a missed member gives a stale key (`=2` catches it on a hit).
- The snapshot reads `liverpool->regs`, the same object as the existing pass 1. On the threaded command
  processor path, `DrawRegs()` is the copy for the draw being bound (`liverpool.h:313`). This is an
  existing choice in this file, not changed here.
- The snapshot compare runs on every draw. If the skip rate is low, it costs more than it saves.
- The `=1` flat-buffer counters copy the flat buffer per refresh. That overhead is in mode 1 too, so do
  not time with mode 1; time with mode 0 and count with mode 1 in separate runs.
- Pass 2 (render target masks, MRT, sample rules) still runs on every draw, since it depends on the
  shader's `mrt_mask`.

## 7. Part 3: GPL fast-link (not implemented)

Facts checked in code:
- No extension in `renderer_vulkan` references `VK_EXT_graphics_pipeline_library` or `pipeline_library`.
- `vk_instance.cpp:399` enables `VK_EXT_vertex_input_dynamic_state` through `add_extension`; the feature
  struct is at `vk_instance.cpp:958`, unlinked when not enabled at `:1032`; the accessor is at
  `vk_instance.h:247`. GPL would follow the same pattern (plus `VK_KHR_pipeline_library`).
- `vk_graphics_pipeline.cpp:428-447`: one `GraphicsPipelineCreateInfo` and one
  `createGraphicsPipelineUnique`. Dynamic states are at `:128-150`. Shader stages at `:158-251`.

Plan, if the gate passes:
1. Measure first. A fast-link on the draw thread replaces a skipped draw with a synchronous build. The
   notes put a sync build at about 36 ms, so fast-link only helps if it is much cheaper. Get the
   `LogSyncPipeline` time per graphics build from a `SOTC_FPS` run before any code.
2. `vk_instance.cpp`: enable the extension and `graphicsPipelineLibrary`, next to the vertex input
   feature. `vk_instance.h`: accessor.
3. `vk_graphics_pipeline.cpp`: split the constructor's create into four libraries (vertex input interface,
   pre-raster, fragment, fragment output) with `VkGraphicsPipelineLibraryCreateInfoEXT`, then a final
   pipeline with `VkPipelineLibraryCreateInfoKHR`, without the link-time-optimization flag. Keep the
   descriptor buffer flag and the layout.
4. `vk_pipeline_cache.cpp`: for `SOTC_PIPE_GPL=1`, build the fast-linked pipeline at the two skip points
   of `GetGraphicsPipeline` (the queued geometry draw and the `QueueAsyncPipeline` branch), and let
   `CollectAsyncPipelines` swap in the optimized one when the worker finishes.
5. Risk: fast-link is cheaper for the vertex input and output libraries only when they are reused across
   pipelines. The shader compile cost stays. Expect little gain unless step 1 shows a large skipped-draw
   count.
